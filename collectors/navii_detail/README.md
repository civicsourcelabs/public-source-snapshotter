# Navii Detail Collector Contract

public repo側で実装するcollectorのCLI contractです。

`collect.py` は公式open data ZIPからdetail URL候補を作り、owner承認時だけdetail HTMLを取得するpublic-source collectorです。external datastore、external-service secret、deploy provider、production secretには接続しません。

## CLI

```bash
python3 collectors/navii_detail/collect.py \
  --source-dir "$SOURCE_DIR" \
  --out-dir "$OUT_DIR" \
  --source-id navii_detail \
  --source-snapshot-date "$SOURCE_SNAPSHOT_DATE" \
  --run-label "$RUN_LABEL" \
  --artifact-mode summary_only \
  --kinds hospital,clinic,dental,pharmacy \
  --shard-count 1 \
  --shard-index 0 \
  --max-pages-per-shard 400 \
  --workers 2 \
  --pause-seconds 0.3 \
  --jitter-seconds 0.1 \
  --timeout-seconds 30 \
  --retry-count 2 \
  --retry-backoff-seconds 2 \
  --fail-on-fetch-error-rate 5 \
  --fail-on-parse-error-rate 0 \
  --fail-on-unresolved-rate 1 \
  --execute
```

## Inputs

- official open data ZIPs under `--source-dir`
- source manifest under `sources/navii/source-manifest.json`
- workflow-derived `source_snapshot_date` and `run_label`

`--insecure-skip-tls-verify` is for owner-approved TLS certificate troubleshooting only. Do not use it as the default path.

The collector must not require:

- external datastore
- payment provider
- deploy provider
- downstream candidate CSV
- service role
- production secret

`source_snapshot_date` and `run_label` are derived by
`collectors/navii_detail/source_readiness.py` in the workflow. They are not
normal workflow inputs.

`detail_url_overrides.json` is a version-controlled exception map for cases
where an official open-data ID no longer identifies the current Navii detail
page. The collector validates this map at startup, tries an override before
the derived ID URL, and records the map hash in `run-metrics.json`. The initial
entry documents the verified `E-0109` case for `1021012511471`.

When a derived URL returns Navii's `E-0109` missing-identifier page, the
collector performs an exact prefecture/kind/name/address search using Navii's
public search page. A single exact match is fetched and recorded as
`search_resolved`; zero, multiple, or mismatched matches are recorded as
`unresolved`. Search-resolved candidates are emitted to
`proposed-detail-url-overrides.json` for later review and normal PR promotion;
the workflow never commits or pushes this file automatically.

For the single-workflow full run, the preflight uses
`--sample-candidates --sample-fraction 0.001` with the same shard and fetch
settings as the full run. `--sample-fraction` selects approximately that
fraction per requested kind; it is not used when `--all-candidates` is set.

## Outputs

`--out-dir` should contain:

```text
candidates.csv.gz
summary.csv.gz
page-coverage.csv.gz
table-rows.csv.gz
links.csv.gz
phone-numbers.csv.gz
coverage-summary.csv.gz
proposed-detail-url-overrides.json
run-metrics.json
quality-status.json
```

`run-metrics.json` must include:

- `schema_version`
- `source_id`
- `source_snapshot_date`
- `run_label`
- `shard_count`
- `shard_index`
- `candidate_count`
- `available_candidate_count`
- `available_candidate_counts`
- `sample_fraction`
- `fetch_ok_count`
- `fetch_error_count`
- `fetch_error_rate`
- `parse_ok_count`
- `parse_error_count`
- `parse_error_rate`
- `quality_status`
- `parser_version`
- `kind_metrics`
- `override_hit_count`, `derived_hit_count`, `search_resolved_count`
- `unresolved_count`, `unresolved_rate_percent`
- `detail_url_override_count`, `detail_url_overrides_hash`
- `proposed_override_count`
- `started_at`
- `completed_at`

`quality-status.json` is generated by the workflow after all shard metrics are
aggregated. An executed handoff is usable only when `quality_status` is
`pass`. A canary requires at least 25 candidates per requested kind and
non-zero section/table/link/phone extraction for every requested kind. An
unresolved detail identifier is not a parse error and does not stop the run;
the source row is retained while Navii-only output is blank. The default
aggregate unresolved threshold is 1.0%; a rate above it fails the gate. A
valid detail page that has a DOM/section/table parse error still fails closed.
The full workflow's preflight uses the same resolution and extraction checks
across its approximately 0.1% sample and records the result in the preflight
audit artifact; its sampled rows are not used as the full handoff input.

`summary.csv.gz` and `page-coverage.csv.gz` include
`navii_detail_status` (`override_hit`, `derived_hit`, `search_resolved`,
`unresolved`, `parse_error`, or `fetch_error`) and a sanitized
`navii_detail_reason`. For `unresolved` rows, the official source fields stay
available, while Navii-only detail URL, table, link, and phone outputs are
blank or absent.

`phone-numbers.csv.gz` contains neutral phone contact rows extracted from target
detail-page tables. Fax rows are excluded when the row label identifies them as
fax/facsimile rows.

`table-rows.csv.gz` contains all extractable detail-page table rows. These rows
use `target_group=all_detail`; target-group coverage remains available in
`summary.csv.gz`, `page-coverage.csv.gz`, and `coverage-summary.csv.gz`.

`links.csv.gz` contains source links found inside detail-page tables, including
the source section, row label, visible text, raw href, and resolved href.

## Public Safety

The collector may write facility-level rows to local shard artifact files, but the workflow must encrypt full artifacts before long-lived public artifact retention.

`summary_only` modeでは、workflowへuploadされるshard packageにraw facility-level full outputを含めません。`encrypted_full` modeでも、raw outputはshard job内で暗号化してからuploadします。

The collector must not write:

- external datastore ids
- downstream processing confidence
- owner review notes
- datastore load script
- secret / token values
